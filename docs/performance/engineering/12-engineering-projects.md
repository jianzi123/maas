# 高级工程练习与实现评审

下面的作业需要提交代码差异、反例和证据。现有八类CPU实验提供可读、可运行的起点；设备、集群和真实模型阶段仍按具体授权。完成文档或算法参考，只在其验证层级判定。

## 练习一 修改在线 Attention

在attention_lab中增加window mask或split-KV归并，先写数学允许范围，再与独立dense参考对照。必须覆盖空块、全遮罩、非整尾块、GQA和极大score。用明确的头值[10,10,20,20]核对分组，防止candidate与oracle一起抄错映射。

提交包含shape表、每case误差、失败输入和峰值中间张量范围。若未来移植GPU，另交成熟backend、真实地址/stride、设备时长、布局准备及模型质量。CPU接近机器精度不等于半精度质量通过。

## 练习二 将 Scheduler 与 Worker 完成接起来

复用KV页池和容量调度器，新增fake Worker事件队列，保持plan/submit/complete分离。把取消、重复完成、旧incarnation、两个batch共享页、缺完成和输出队列满排列成确定事件轨迹。

至少证明：未完成页不复用、同batch不双pin、COW OOM不破坏原引用、旧generation不能解除新分配、取消后无新提交、实际/预留页不超容量。真实GPU接入还要提供所有相关stream完成或隔离证据。

该边界已由[第13章受控CPU闭环](13-runtime-loop.md)接续实现：保留原调度策略和页池，引入不可变计划、Worker回包、输出信用与停止回收。真实GPU/模型及平台适配仍按R2与E1的授权条件推进。

## 练习三 为恢复实验增加一个故障

在已存在资源与journal applied之间制造冲突，或将原资源替换为不同归属。应保持原命令状态可查、拒绝错误认领，不生成新command猜成功，不删除无权资源。

写出prepare、外部动作、回查、applied和ACK各阶段的状态图。对每个故障保存退出码、恢复前后记录、唯一资源/提交次数。项目端口由原后端维护，不能把教学SQLite schema直接部署到MySQL或让Operator写核心账本。

## 练习四 设计并否证一项优化

从真实profile选择一项K/R课题；没有真实profile时只交机制假设和采样计划。冻结模型/版本/资源/精度/负载/业务规则，采用成熟baseline，一次只改一个因素。

算子交数值、全部输出、normal timing与profiler解释；运行时交J02分层、queue/KV/Graph、质量、显存、失败/拒绝/pending与G；端到端再加实际Go/Higress路由、账本、取消和清理。采用配对run统计，保留负结果和未达到的分位数。

## 评审时逐项追问

| 维度 | 必须能展示的材料 | 明确失败例 |
|---|---|---|
| 数学与精度 | 独立参考、位置/布局/舍入、误差与finite | 同样抄错mask；漏输出；事后放宽容差 |
| 地址与资源 | stride、页表、代次、引用、pin、峰值/预留 | free只看refs；旧回包释放新页 |
| 并发与恢复 | owner、提交/完成、稳定命令、ACK读回 | 超时换ID重试生成；网络调用占账本长锁 |
| 调度与公平 | 触发负载、容量策略、长短分层、背压 | 只报短请求均值；删pending或长请求 |
| 对照与统计 | 成熟baseline、范围一致、run级配对、删失 | naive对照；请求伪重复；恢复者p95冒充全体 |
| 部署与业务 | 原UID/活动修订/固定来源、真实证据、唯一账本 | PodReady代替Callable；slot回收退款 |
| 可复现 | SHA/输入hash/配置、原始日志、命令与限制 | 仅截图百分比；fixture冒充模型收益 |

评审应逐项引用实现和证据。当前CPU实现、固定源码和本地故障证据可以直接检查；CUDA/Triton执行、真实多卡/模型质量和生产发布仍须对应资源与独立验证。
